# Implementation Plan: QBox Buildroot ARM64 SoC Boot Lane

## Preconditions

- Current working directory: `/build/qbox_dev`.
- QBox submodule present at `qbox/`.
- QBox branch checked out as intended for development.
- No uncommitted changes before implementation starts.
- Baseline check passes:

```bash
bash scripts/check_arm64_boot_lane.sh
```

## Phase 0: baseline capture

1. Record QBox commit and branch:

   ```bash
   git -C qbox branch --show-current
   git -C qbox rev-parse HEAD
   git submodule status --recursive
   ```

2. Confirm current AArch64 boot baseline:

   ```bash
   bash scripts/check_arm64_boot_lane.sh
   ```

3. Capture the current plan/spec references in the implementation report.

Deliverable:

- `doc/verification/qbox-buildroot-arm64-baseline-YYYY-MM-DD.md`.

## Phase 1: Buildroot external tree scaffold

Create:

```text
buildroot/external/qbox_arm64/
  Config.in
  external.mk
  board/qbox/a710_soc/
    linux.config
    rootfs_overlay/
    post-build.sh
    post-image.sh
    genimage.cfg
    qbox_a710_soc.dts
  configs/qbox_a710_soc_defconfig
```

Minimum defconfig contents:

```text
BR2_aarch64=y
BR2_TOOLCHAIN_BUILDROOT=y
BR2_LINUX_KERNEL=y
BR2_LINUX_KERNEL_IMAGE=y
BR2_TARGET_ROOTFS_CPIO=y
BR2_TARGET_GENERIC_HOSTNAME="qbox-a710"
BR2_TARGET_GENERIC_ISSUE="QBox A710 Buildroot"
```

Notes:

- Pin the actual kernel tag or commit used during implementation.
- Keep downloaded Buildroot source and output under ignored build/tool paths.
- Do not place generated images under source control.

Verification:

```bash
make -C buildroot O=/build/qbox_dev/build/buildroot-a710 \
  BR2_EXTERNAL=/build/qbox_dev/buildroot/external/qbox_arm64 \
  qbox_a710_soc_defconfig
make -C buildroot O=/build/qbox_dev/build/buildroot-a710 -j"$(nproc)"
```

Pass criteria:

- `build/buildroot-a710/images/Image` exists.
- `build/buildroot-a710/images/rootfs.cpio` exists.
- `build/buildroot-a710/images/qbox_a710_soc.dtb` exists or is generated by the
  post-image step.

## Phase 2: QBox Buildroot platform scaffold

Create:

```text
qbox/platforms/buildroot/
  conf_aarch64.lua
  fw/
    arm64_bootloader.lua
    Artifacts/
```

Implementation steps:

1. Copy `qbox/platforms/ubuntu/conf_aarch64.lua` to the Buildroot platform.
2. Copy or reuse `qbox/platforms/ubuntu/fw/arm64_bootloader.lua`.
3. Change CPU count from 8 to 4.
4. Change CPU model from `cpu_arm_cortexA76` to `cpu_arm_cortexA710`.
5. Change loaded artifact names:
   - kernel: `fw/Artifacts/Image.bin`.
   - DTB: `fw/Artifacts/qbox_a710_soc.dtb`.
   - initramfs: `fw/Artifacts/rootfs.cpio`.
6. Preserve DRAM base and load offsets for the first boot.

Verification:

```bash
rg -n 'ARM_NUM_CPUS|cpu_arm_cortexA710|qbox_a710_soc.dtb|rootfs.cpio' \
  qbox/platforms/buildroot/conf_aarch64.lua
```

## Phase 3: artifact staging

Create a staging script or CMake target that copies Buildroot outputs into the
QBox platform artifact directory.

Minimum shell shape:

```bash
install -D build/buildroot-a710/images/Image \
  qbox/platforms/buildroot/fw/Artifacts/Image.bin
install -D build/buildroot-a710/images/qbox_a710_soc.dtb \
  qbox/platforms/buildroot/fw/Artifacts/qbox_a710_soc.dtb
install -D build/buildroot-a710/images/rootfs.cpio \
  qbox/platforms/buildroot/fw/Artifacts/rootfs.cpio
```

Pass criteria:

```bash
ls -l qbox/platforms/buildroot/fw/Artifacts/Image.bin \
      qbox/platforms/buildroot/fw/Artifacts/qbox_a710_soc.dtb \
      qbox/platforms/buildroot/fw/Artifacts/rootfs.cpio
```

## Phase 4: QBox build

Use the existing preset or an explicit build directory:

```bash
cd /build/qbox_dev/qbox
cmake --preset gcc -DLIBQEMU_TARGETS=aarch64
cmake --build --preset gcc --parallel
```

Pass criteria:

- `qbox/build/platforms/platforms-vp` exists.
- AArch64 QEMU target libraries are present in the build/install output.

## Phase 5: first boot smoke

Run:

```bash
mkdir -p /build/qbox_dev/build/verification
cd /build/qbox_dev/qbox
timeout --signal=SIGQUIT 120s \
  ./build/platforms/platforms-vp -l platforms/buildroot/conf_aarch64.lua \
  2>&1 | tee /build/qbox_dev/build/verification/qbox-a710-buildroot-boot.log
```

Pass criteria:

- PL011 console receives kernel output.
- Kernel reaches initramfs userspace.
- BusyBox init or shell starts.
- No fatal GIC, timer, DTB, or PSCI errors appear.

Recommended log checks:

```bash
rg -n 'Linux version|psci|GIC|ttyAMA|Freeing unused kernel memory|BusyBox|init' \
  /build/qbox_dev/build/verification/qbox-a710-buildroot-boot.log
```

## Phase 6: ext4 rootfs follow-up

Only after initramfs boot works:

1. Enable ext4 rootfs in Buildroot.
2. Stage `rootfs.ext4`.
3. Enable virtio block root in the QBox platform.
4. Use bootargs:

   ```text
   console=ttyAMA0 earlycon=pl011,0x10000000 root=/dev/vda rw rootwait loglevel=8
   ```

Pass criteria:

- `/dev/vda` appears.
- rootfs mounts read-write.
- init completes.

## Rollback plan

If the Buildroot lane breaks the workspace:

1. Remove or revert `qbox/platforms/buildroot/` changes.
2. Remove Buildroot artifact staging outputs.
3. Keep `qbox/platforms/ubuntu/` untouched.
4. Re-run `bash scripts/check_arm64_boot_lane.sh` to prove the baseline still
   exists.
