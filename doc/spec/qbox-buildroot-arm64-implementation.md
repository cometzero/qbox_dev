# Implementation Plan: Apollo SoC / apollo-qbox Buildroot Boot Lane

## Preconditions

- Current working directory: `/build/qbox_dev`.
- QBox submodule present at `sources/qbox/`.
- Buildroot source submodule present at `sources/buildroot/`.
- Linux source submodule present at `sources/linux/`.
- QEMU/libqemu source submodule present at `sources/qemu/`.
- QBox branch checked out as intended for development.
- No uncommitted changes before implementation starts.
- Baseline check passes:

```bash
bash scripts/check_arm64_boot_lane.sh
```

## Phase 0: baseline capture

1. Record QBox commit and branch:

   ```bash
   git -C qbox branch --show-current
   git -C qbox rev-parse HEAD
   git submodule status --recursive
   ```

2. Confirm current AArch64 boot baseline:

   ```bash
   bash scripts/check_arm64_boot_lane.sh
   ```

3. Capture the current plan/spec references in the implementation report.

Deliverable:

- `doc/verification/qbox-buildroot-arm64-baseline-YYYY-MM-DD.md`.

## Phase 1: Buildroot external tree scaffold

Create:

```text
configs/buildroot/external/apollo_qbox/
  Config.in
  external.mk
  board/apollo/apollo-qbox/
    rootfs_overlay/
    post-build.sh
    post-image.sh
    genimage.cfg
  configs/apollo_qbox_defconfig
configs/linux/
  linux.config
  apollo_soc.dts
```

Minimum defconfig contents:

```text
BR2_aarch64=y
BR2_TOOLCHAIN_BUILDROOT=y
BR2_TARGET_ROOTFS_CPIO=y
BR2_PACKAGE_HOST_DTC=y
BR2_TARGET_GENERIC_HOSTNAME="apollo-qbox"
BR2_TARGET_GENERIC_ISSUE="Apollo QBox Buildroot"
```

Notes:

- Do not set `BR2_LINUX_KERNEL*`; Linux is built from `sources/linux`.
- Pin the actual kernel tag or commit in the Linux submodule and report.
- Keep downloaded Buildroot source and output under ignored build/tool paths.
- Do not place generated images under source control.

Verification:

```bash
scripts/build_qbox_buildroot_arm64.sh --config-only
scripts/build_qbox_buildroot_arm64.sh
```

Pass criteria:

- `build/buildroot-a710/images/rootfs.cpio` exists.
- `build/buildroot-a710/images/apollo_soc.dtb` exists or is generated by the
  post-image step.
- Buildroot `.config` has no `BR2_LINUX_KERNEL=y`.

## Phase 1.5: standalone Linux kernel build

Build the kernel from the separate Linux source submodule. Reuse the Buildroot
internal toolchain so the ABI and userspace target stay aligned while keeping
Buildroot out of kernel compilation.

Verification:

```bash
scripts/build_qbox_linux_arm64.sh --config-only
scripts/build_qbox_linux_arm64.sh
```

Pass criteria:

- `sources/linux` is a git submodule pinned to the selected upstream tag/commit.
- `build/linux-a710/arch/arm64/boot/Image` exists and is non-empty.
- The merged Linux config includes PL011, GICv3, PSCI, and initrd support.

## Phase 2: QBox Buildroot platform scaffold

Create:

```text
sources/qbox/platforms/buildroot/
  conf_aarch64.lua
  fw/
    arm64_bootloader.lua
    Artifacts/
```

Implementation steps:

1. Copy `sources/qbox/platforms/ubuntu/conf_aarch64.lua` to the Buildroot platform.
2. Copy or reuse `sources/qbox/platforms/ubuntu/fw/arm64_bootloader.lua`.
3. Change CPU count from 8 to 4.
4. Change CPU model from `cpu_arm_cortexA76` to `cpu_arm_cortexA710`.
5. Change loaded artifact names:
   - kernel: `fw/Artifacts/Image.bin`.
   - DTB: `fw/Artifacts/apollo_soc.dtb`.
   - initramfs: `fw/Artifacts/rootfs.cpio`.
6. Preserve DRAM base and load offsets for the first boot.

Verification:

```bash
rg -n 'ARM_NUM_CPUS|cpu_arm_cortexA710|apollo_soc.dtb|rootfs.cpio' \
  sources/qbox/platforms/buildroot/conf_aarch64.lua
```

## Phase 3: artifact staging

Create a staging script or CMake target that copies the standalone Linux image
and Buildroot rootfs/DTB outputs into the QBox platform artifact directory.

Minimum shell shape:

```bash
install -D build/linux-a710/arch/arm64/boot/Image \
  sources/qbox/platforms/buildroot/fw/Artifacts/Image.bin
install -D build/buildroot-a710/images/apollo_soc.dtb \
  sources/qbox/platforms/buildroot/fw/Artifacts/apollo_soc.dtb
install -D build/buildroot-a710/images/rootfs.cpio \
  sources/qbox/platforms/buildroot/fw/Artifacts/rootfs.cpio
```

Pass criteria:

```bash
ls -l sources/qbox/platforms/buildroot/fw/Artifacts/Image.bin \
      sources/qbox/platforms/buildroot/fw/Artifacts/apollo_soc.dtb \
      sources/qbox/platforms/buildroot/fw/Artifacts/rootfs.cpio
```

## Phase 4: QBox build

Use the workspace wrapper so QBox gets ccache and builds libqemu from the local
QEMU source submodule instead of downloading it into `_deps`:

```bash
scripts/build_qbox_buildroot_platform.sh --config-only
scripts/build_qbox_buildroot_platform.sh
```

Pass criteria:

- `sources/qbox/build/platforms-vp` exists.
- AArch64 QEMU target libraries are present in the build/install output.
- `sources/qbox/build/CMakeCache.txt` records
  `libqemu_SOURCE_DIR=/build/qbox_dev/sources/qemu`.

## Phase 5: first boot smoke

Run:

```bash
mkdir -p /build/qbox_dev/build/verification
cd /build/qbox_dev/sources/qbox
timeout --signal=SIGQUIT 120s \
  ./build/platforms-vp -l platforms/buildroot/conf_aarch64.lua \
  2>&1 | tee /build/qbox_dev/build/verification/apollo-qbox-buildroot-boot.log
```

Pass criteria:

- PL011 console receives kernel output.
- Kernel reaches initramfs userspace.
- BusyBox init or shell starts.
- No fatal GIC, timer, DTB, or PSCI errors appear.

Recommended log checks:

```bash
rg -n 'Linux version|psci|GIC|ttyAMA|Freeing unused kernel memory|BusyBox|init' \
  /build/qbox_dev/build/verification/apollo-qbox-buildroot-boot.log
```

## Phase 6: ext4 rootfs follow-up

Only after initramfs boot works:

1. Enable ext4 rootfs in Buildroot.
2. Stage `rootfs.ext4`.
3. Enable virtio block root in the QBox platform.
4. Use bootargs:

   ```text
   console=ttyAMA0 earlycon=pl011,0x10000000 root=/dev/vda rw rootwait loglevel=8
   ```

Pass criteria:

- `/dev/vda` appears.
- rootfs mounts read-write.
- init completes.

## File ownership

| Path | Owner |
| --- | --- |
| `configs/buildroot/external/apollo_qbox/` | Buildroot rootfs/DTB lane. |
| `sources/buildroot/` | Buildroot upstream source submodule. |
| `sources/linux/` | Linux upstream source submodule. |
| `sources/qemu/` | QEMU/libqemu upstream source submodule consumed by QBox. |
| `sources/qbox/platforms/buildroot/` | QBox platform lane. |
| `scripts/` | Workspace helper scripts only. |
| `doc/` | Plans, specs, and verification reports. |
| `sources/qbox/platforms/ubuntu/` | Existing Ubuntu lane; avoid changes unless explicitly approved. |

## Rollback plan

If the Buildroot lane breaks the workspace:

1. Remove or revert `sources/qbox/platforms/buildroot/` changes.
2. Remove Buildroot artifact staging outputs.
3. Keep `sources/qbox/platforms/ubuntu/` untouched.
4. Re-run `bash scripts/check_arm64_boot_lane.sh` to prove the baseline still
   exists.
