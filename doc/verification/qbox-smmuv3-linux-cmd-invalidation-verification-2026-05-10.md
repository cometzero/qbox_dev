# QBox SMMUv3 Linux CMDQ Invalidation Verification - 2026-05-10

## Scope

Linux guest-driven CMDQ invalidation functional slice for SMMU-COMP-020,
SMMU-COMP-030, and SMMU-COMP-080.

The slice extends the Apollo Linux probe so the guest-visible SMMUv3 CMDQ model
receives ATC_INV and TLBI_NH_ALL commands during boot. The probe checks the TBU
architected command status register and fails boot probing if the modeled ATS
invalidation counter does not advance.

This is not full upstream Linux `arm-smmu-v3` invalidation compliance. The
commands are still generated by the Apollo probe driver against the QBox
functional model rather than by the generic upstream driver lifecycle for PASID,
CD install/remove, and endpoint ATC completion ordering.

## Implementation

- `sources/linux/drivers/soc/apollo/apollo-hexagon-test.c` now defines
  `APOLLO_TBU_FEATURE_ARCH_CMD_INVALIDATION`, `APOLLO_SMMUV3_ARCH_CMD_ATC_INV`,
  and `APOLLO_SMMUV3_ARCH_CMD_TLBI_NH_ALL`.
- The Linux probe writes a four-command CMDQ sequence: `CMD_SYNC`,
  `CMD_PRI_RESP`, `ATC_INV`, and `TLBI_NH_ALL`.
- The probe validates `CMDQ_CONS == 4`, CMDQ sync status, and non-zero modeled
  invalidation count through `APOLLO_TBU_REG_ARCH_CMD_STATUS`.
- `scripts/run_iree_tiny_cnn_hexagon_qbox_guest_smoke.sh` now gates runtime on
  the Linux marker plus TBU `ATC_INV` and `TLBI_NH_ALL` invalidation logs.
